# 01 — Research

## Use / Owner

Use for exploring a problem before choosing a bounded increment. RESEARCHER supplies evidence; the parent owns routing and user decisions. This is an execution aid, not a fixed Research gate or a request to start an application.

## Read / Inputs

Read [Research](../../process.md#1-research) in full and the router-required [shared contract](../../process.md#shared-roles-and-parent-handoff-contract) and [artifact policy](../../process.md#external-artifacts-and-review-records). Inputs are the user's question, known constraints, and relevant existing sources. No pre-existing planning documents or target `AGENTS.md` are required; read applicable instructions if present.

## Execute

1. Confirm the question, target context if any, investigation boundary, and intended recipient. Do not silently turn exploration into product decisions.
2. For delegated web work, preflight the actual child providers registering `web_search`, `fetch_content`, `get_search_content`, and `source_check`. Installation of `pi-web-access` alone is insufficient. Missing registration blocks that work; do not substitute bash fetching or another delegation mechanism.
3. Investigate authoritative sources and relevant repository evidence. Distinguish verified facts, inference, uncertainty, and conflicting sources; cite paths/URLs and version applicability.
4. Discuss options and emerging opinions in conversation. Without an artifact agreement, obtain approval before fetched caches, notes, or other runtime artifact writes. Authorized planning source work remains possible; no unsolicited research report is required.

## Handoff / Stop

Return concise conclusions, sources, tradeoffs, and open questions. Research has no mandatory deliverable, prescribed duration, or completion gate. Continue exploring if useful; move to [Planning](02-planning.md) only when the user chooses a concrete increment. Pause at the requested stop point; do not install tools, create an app, or begin later stages implicitly.
